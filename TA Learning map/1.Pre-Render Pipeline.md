## 1. 为什么使用 GPU 而不是 CPU

游戏刷新率（Refresh Rate，单位 Hz）对游戏体验影响巨大：

| 场景 | 所需帧率 |
|------|----------|
| 正常游戏体验 | ≥ 30 FPS |
| 流畅游戏体验 | ≥ 60 FPS     |
| Sony VR 平台 | ≥ 90 FPS（双目） |

以 iPhone Xs Max 为例，达到 30 FPS 需要的计算量级为：

```
分辨率（Resolution）2688 × 1242
  × 帧率（Frame Rate）30
  × 填充率（Fill Rate，平均最小 3）
  × 单像素计算步骤数 n
= 十亿至百亿级运算
```

### CPU vs GPU 对比

| 特性 | CPU | GPU |
|------|-----|-----|
| 擅长任务 | 少量复杂的逻辑运算 | 海量简单的并行计算 |
| 核心数 | 少（多核结构 Multi-core Architecture，但每核串行） | 成千上万（流处理器 Stream Processor） |
| 逻辑控制 | 强（分支预测 Branch Prediction、缓存 Cache） | 弱（芯片上逻辑运算和缓存较少） |
| 实测性能 | 绘制 1024×1024 贴图：272.1 ms / 3.7 FPS | 绘制 1024×1024 贴图：0.4 ms / 2237.6 FPS |

> **比喻：** CPU 像雕刻大师，能做出精美作品但无法批量生产；GPU 像玩具工厂，有大量流水线工人，每天生产数万件毫无压力，但做不出流芳百世的雕塑。

## 2. GPU 原理

### 2.1 发展历程

图形加速硬件因取纹理数据（Texture Data）、三角面内像素插值（Pixel Interpolation）、深度测试（Depth Test）等需求而出现。GPU 在过去几十年发展极快，总体趋势为

> **从可配置的固定管线（Fixed-Function Pipeline）→ 可自定义算法的编程模块（Programmable Pipeline）**

### 2.2 数据并行结构（Data Parallel Architecture）

对任何处理器而言，**缩小延迟（Latency）** 是核心目标。访问存储芯片（Memory Chip）远比访问本地寄存器（Local Register）耗时，处理器在等待数据时处于停滞状态。

现代计算机结构中，Local Register本地寄存器与Me的位置是寄存器s小型高的高速临时数据暂存单元，而存储芯片则是独立于CPUdu。因此读取数据的时候会具有非常大的时间差异。

**CPU 的延迟应对策略：**
- 多核结构（Multi-core Architecture）
- 本地缓存（Local Cache）
- 分支预测（Branch Prediction）
- 结构重组（Reordering = Out-of-Order Execution）

**GPU 的延迟应对策略：** 根本不同——芯片内有成千上万个 shader 运算核（Shader Core），作为流处理器（Stream Processor）按顺序同时处理大量相似数据。核心设计原则是**让调用相互独立**，消除相邻核心间的等待问题。
>
> Stream Processor：专门用于处理持续不断且实施到达的sh
>
> Shader Core：GPU上数量最多、功能最单一的可编程执行单元

### 2.3 SIMD：单指令多数据（Single Instruction Multiple Data）

GPU 使用 **SIMD** 架构来减小延迟。核心思路：运算延迟远小于数据访问延迟。

**饭店比喻理解 SIMD：**

| 角色 | 对应 GPU 概念 |
|------|---------------|
| 1 个大厨 | 1 个运算核心（Shader Core） |
| 10 个菜 | 10 个像素（Pixel） |
| 10 个助手 | 纹理数据访问请求 |
| 菜谱+做菜 1 分钟 | 代数运算（Algebraic Operation） |
| 备菜 8 分钟 | 访问数据延迟 |

- 串行方式：大厨每道菜等助手备菜 → 10 道菜需 100 分钟
- SIMD 方式：大厨先给 10 个助手分别下菜谱，第一个助手备完时大厨正好可以开始做第一道菜 → 只需 20 分钟

### 2.4 线程与线程束（Thread & Warp）

| 概念 | 说明 |
|------|------|
| GPU 线程（GPU Thread） | 每个像素的 shader 调用称为一个线程，带有一点输入内存和运行寄存器 |
| 线程束（Warp） | 使用相同 shader 的线程组合成线程束。英伟达（NVIDIA）GPU 中一个线程束包含 32 个线程 |
| 线程束调度 | 线程束 1 停滞等待数据时，线程束 2 开始运行，依次轮转 |

> 以英伟达 GPU 为例：计算 2000 个像素需要 ⌈2000 / 32⌉ = 63 个线程束（Warp）。

## 3. 渲染管线（R恩的人pender Pipeline）

渲染管线的定义如下：A render pipeline performs a series of operations that take the contents of a S ,and displays them on a screen.(渲染管线执行读取chang'jing'nei内一系列内容并呈现在ping'mu'shang)

### 3.1 流水线概念（Pipeline）

流水线（Pipeline）是指将一个任务切分为多个阶段（Stage），各阶段共同完成更大的任务。

- **瓶颈决定速度：** 流水线的速度由最慢的阶段决定
- **并行提升：** 多条流水线可并行存在，提高效率

### 3.2 渲染管线的四大阶段

渲染管线（Render Pipeline）是实时渲染（Real-Time Rendering）的核心组件，目的是通过虚拟相机（Virtual Camera）、三维物体（3D Object）、光源（Light Source）等生成二维画面。

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  应用阶段     │ →  │  几何运算     │ →  │  光栅化       │ →  │  像素运算     │
│ Application  │    │ Geometry     │    │ Rasterization│    │ Pixel        │
│ Stage       │    │ Stage        │    │ Stage        │    │ Processing   │
│ (CPU)       │    │ (GPU)        │    │ (GPU)        │    │ (GPU)        │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

## 4. 应用阶段（Application Stage）

### 4.1 特征

| 特性 | 说明\[由程序驱动故叫应用阶段]     |
|------|------|
| 执行位置 | CPU 端 |
| 控制权 | 开发者拥有绝对控制权，可自定义功能 |
| 可分割性 | 无法切分为子阶段，但可通过多线程（Multithreading）并行处理 |
| 影响 | 此阶段的优化（如剔除算法 Culling Algorithm）会影响其他阶段的效率 |

### 4.2 典型任务

- 用户输入处理（User Input Handling）
- 碰撞检测（Collision Detection）
- 动画（Animation）
- 物理模拟（Physics Simulation）
- 全局加速算法（Global Acceleration Algorithm）
- 剔除算法（Culling Algorithm）：视锥剔除（Frustum Culling）、遮挡剔除（Occlusion Culling）等

### 4.3 输出

阶段结束时，将需要渲染的数据传入下一阶段，包括：
- 几何元素/图素（Primitive）：点（Point）、线（Line）、三角面（Triangle）
- 纹理（Texture）
- 渲染参数（Rendering Parameters）

> 部分应用阶段工作也可通过 Compute Shader 交给 GPU 处理，将 GPU 当作高并行的通用处理器使用。

## 5. 几何运算阶段（Geometry Stage）

此阶段处理形体变换（Transformation）、投影（Projection）和其他逐顶点（Per-Vertex）或逐三角面（Per-Triangle）的几何操作，决定**绘制对象是什么、如何绘制和绘制位置**。

分为四个子阶段：

```
顶点着色 → 可选顶点过程 → 剪裁 → 屏幕映射
Vertex    Optional       Clipping  Screen
Shading   Vertex                    Mapping
          Processes
```

### 5.1 顶点着色阶段（Vertex Shading Stage）

#### 5.1.1 Shader 的含义

Shader 一词与 Shadow（阴影）同源，是描述光照在物体上产生阴影的动词。在图形学中的定义为：**光在材质上产生光影色彩效果的运算**（狭义）。

#### 5.1.2 核心任务

| 任务 | 说明 |
|------|------|
| 顶点位置计算 | 一系列坐标变换（Coordinate Transformation） |
| 法线输出 | 输出顶点法线（Normal）方向 |
| 纹理坐标输出 | 输出 UV 坐标（Texture Coordinate） |

> UV Coordinates：即UV坐标(UVs)，图形学中区分yuuan'm二维坐标zhon(0,0)在纹理左下角，(1,1)在纹理右上角
>
> UV Unwrapping：即UV展开，将一个3D模型zhan ping'mi其中mei'ge'ding'dian'dui'ying'de'z其顶点的UV坐标【三角面ke'yi'wan'qu】
>
> 现代 GPU 中很多着色计算已逐像素化（Per-Pixel），顶点着色器（Vertex Shader）更多用于顶点数据本身的处理，如顶点动画（Vertex Animation）、法线修改（Normal Modification）。

#### 5.1.3 坐标变换链

```
模型空间          世界空间          相机空间          剪裁空间
Model Space  →   World Space  →   Camera Space  →   Clip Space
(Object Space)                   (View Space)
```

| 变换 | 矩阵 | 说明 |
|------|------|------|
| 模型变换（Model Transform） | 模型矩阵（Model Matrix） | 模型空间 → 世界空间 |
| 视图变换（View Transform） | 视图矩阵（View Matrix） | 世界空间 → 相机空间 |
| 投影变换（Projection Transform） | 投影矩阵（Projection Matrix） | 相机空间 → 剪裁空间 |

#### 5.1.4 两种投影方式

| 投影方式 | 英文名 | 视觉空间形状 | 特征 |
|----------|--------|-------------|------|
| 正交投影（平行投影） | Orthographic Projection (Parallel Projection) | 立方体（Cube） | 平行线维持平行 |
| 透视投影 | Perspective Projection | 截断金字塔（Frustum） | 平行线可能在地平线相交 |

#### 5.1.5 输入整合器（Input Assembler）

在顶点着色器之前的阶段，DirectX 中称为输入整合器（Input Assembler），功能包括：
- 将流数据（Stream Data）编为集合传入管线
- 根据顶点和颜色数组生成三角面
- 实现 GPU Instancing（GPU 实例化）：一个物体通过变换数据完成多次绘制，只占用一个 Draw Call（绘制调用）

#### 5.1.6 顶点着色器的限制

> 顶点着色器（Vertex Shader）**无法创造或删除顶点**，也无法获取周围顶点的信息，每个顶点都是独立处理的。

### 5.2 可选顶点过程（Optional Vertex Processes）

在必经的顶点过程之后，GPU 可执行以下可选阶段（顺序固定）：

```
细分曲面 → 几何着色 → 流输出
Tessellation  Geometry    Stream
              Shader      Output
```

#### 5.2.1 细分曲面（Tessellation）

| 特性 | 说明 |
|------|------|
| 功能 | 在原有几何体（Geometry）上增加顶点和三角面 |
| 优势 | GPU 增加顶点开销小，可降低带宽（Bandwidth）、节省内存（Memory） |
| 应用 | 低模变圆润、配合置换贴图（Displacement Mapping）丰富细节 |

> 注意：并非所有 GPU 都支持这些可选过程。例如移动端 GPU 一般不支持几何着色器（Geometry Shader）。

#### 5.2.2 几何着色器（Geometry Shader）

| 特性 | 说明 |
|------|------|
| 输入 | 顶点、线段、三角面 |
| 功能 | 生产新顶点和三角面，不限于原有图素（Primitive）上 |
| 应用 | 粒子（Particle）生成、草原实现、毛发模拟（Hair Simulation） |

#### 5.2.3 流输出（Stream Output）

将 GPU 当作几何处理器，处理后的信息存在数组里，由 CPU 或 GPU 进行后续操作。

### 5.3 剪裁（Clipping）

**目的：** 只有部分或全部在视觉空间（View Space）内的图素（Primitive）才会被传入后续阶段并渲染到屏幕。

| 情况 | 处理方式 |
|------|----------|
| 完全在视觉空间内 | 直接传递 |
| 完全在视觉空间外 | 丢弃 |
| 部分在视觉空间内 | 剪裁：在与视觉空间相交处生成新顶点 |

> 使用视觉单位立方体（Unit Cube）的好处是使剪裁问题更容易处理。

**齐次坐标（Homogeneous Coordinate）：** 剪裁阶段使用四维齐次坐标。因为透视投影后，三角面无法使用线性插值（Linear Interpolation），第四个分量（w）的作用就是实现**透视修正插值（Perspective-Correct Interpolation）**。

### 5.4 屏幕映射（Screen Mapping）

将剪裁后的三维坐标（3D Coordinate）——此时称为窗口坐标（Window Coordinate）——进行映射：

| 分量 | 映射目标 |
|------|----------|
| x, y | 缩放到屏幕像素范围 → 屏幕坐标（Screen Coordinate） |
| z | 映射到 [0, 1] 区间 |

> **注意：** 不同图形 API 的 y 轴原点（Origin）和方向不同。例如 OpenGL 的 y 轴原点在左下角向上，DirectX 的 y 轴原点在左上角向下。

## 6. 光栅化阶段（Rasterization Stage）

光栅化的作用是将屏幕空间的二维顶点及其深度等数据转化为屏幕像素（Pixel = Picture Element）。

分为两个子阶段：

### 6.1 三角面设置（Triangle Setup）

| 项目 | 说明 |
|------|------|
| 输入 | 三个顶点形成的三角面 |
| 计算 | 微分方程（Differential Equation）、边的等式（Edge Equation）等数据 |
| 用途 | 用于三角形遍历及几何阶段产生的着色数据插值（Interpolation） |
| 执行方式 | 专用的固定功能芯片硬件 |

### 6.2 三角形遍历（Triangle Traversal）

| 项目 | 说明 |
|------|------|
| 功能 | 判断三角形与像素（采样点 Sampling Point）的交叠 |
| 输出 | 片元（Fragment）：包含三个顶点间的插值数据（含深度） |
| 判定方式 | 取决于 GPU 管线设置 |

**像素与三角形重叠判定方式：**

| 方式 | 英文 | 说明 |
|------|------|------|
| 像素中心判定 | Pixel Center Test | 最简单，看像素中心是否在三角形内 |
| 超采样抗锯齿 | Supersampling Anti-Aliasing (SSAA) | 以更高分辨率渲染再下采样 |
| 多重采样抗锯齿 | Multisample Anti-Aliasing (MSAA) | 只在边缘多重采样，性能开销更小 |

## 7. 像素运算阶段（Pixel Processing Stage）

此阶段所有计算都是**逐像素（Per-Pixel）** 的。每个图素内的像素（而非屏幕内的像素）都会使用一段程序确定可见性（如深度测试 Depth Test）和颜色。

分为两个子阶段：

### 7.1 像素着色阶段（Pixel Shading Stage）

| 项目 | 说明 |
|------|------|
| 输入 | 插值着色数据 |
| 输出 | 一种或多种颜色，传入合并阶段 |
| 可编程性 | GPU 核心可编程 |
| 程序名称 | 像素着色器（Pixel Shader，DirectX）/ 片元着色器（Fragment Shader，OpenGL） |

> **片元（Fragment）** 的定义：三角面全部或部分覆盖单个像素的部分。

**核心技术：**

| 技术 | 说明 |
|------|------|
| 纹理技术（Texturing） | 将不同图像粘贴在物体上，可实现各种效果 |
| 片元丢弃（Fragment Discard） | 像素着色器可选择丢弃某些片元（如 Alpha Cutoff） |
| 视差贴图（Parallax Mapping） | 像素阶段的重要纹理技术应用 |

### 7.2 合并阶段（Merger Stage / Output Merger）

| 项目 | 说明 |
|------|------|
| 目的 | 将像素着色算出的片元颜色与颜色缓存（Color Buffer）中的颜色混合 |
| 可编程性 | **不可编程**，但可配置以实现多种效果 |
| 可见性 | 通过 z 缓冲（Z-Buffer / Depth Buffer）算法完成 |

#### 7.2.1 Z 缓冲算法（Z-Buffer Algorithm）

```
当图素某像素被渲染时：
  其 z 值（深度值）与 Z-Buffer 中同像素的值比较
  ├── z 值更小（更近） → 渲染该像素，更新 Z-Buffer 和 Color Buffer
  └── z 值更大（更远） → 无变化，丢弃
```

| 特性 | 说明 |
|------|------|
| 算法复杂度 | O(n)，非常简单 |
| 局限 | 一个像素只能存一个深度，**无法用于半透明图素（Translucent Object）** |
| 半透明处理 | 必须在所有不透明物体绘制后进行（传统 Z-Buffer 的弱点） |

#### 7.2.2 Early-Z / Pre-Z 技术

传统深度测试在合并阶段进行，导致被抛弃的像素也进行了像素着色（浪费）。现代 GPU 在像素着色**之前**进行深度测试，称为 **Early-Z**（Early Depth Test）或 **Pre-Z**（Pre-Depth Pass）。

> **失效条件：** 如果像素着色器会修改深度或丢弃片元（Alpha Cutoff），则 Early-Z 失效。

#### 7.2.3 其他缓冲与通道

| 缓冲/通道 | 英文名 | 功能 |
|-----------|--------|------|
| Alpha 通道 | Alpha Channel | 存储每个颜色的透明度 |
| 深度缓冲 | Depth Buffer (Z-Buffer) | 存储每像素的深度值 |
| 模板缓冲 | Stencil Buffer | 记录图素位置，控制是否写入颜色缓冲与深度缓冲 |
| 颜色缓冲 | Color Buffer | 存储像素最终颜色 |
| 帧缓存 | Frame Buffer | 上述所有缓存的统称 |

**Alpha 测试（Alpha Test）：** 在旧 API 中可通过 Alpha 测试忽略透明像素的绘制，使其不影响深度缓冲。现代 API 中可在像素着色器中随时按需丢弃像素。

**模板缓冲应用举例：** 可实现只有通过特殊镜片才能看到的文字、非欧几何效果等。

#### 7.2.4 双缓存技术（Double Buffering）

为防止使用者看到画面填充过程，使用双缓存技术：当一个缓存渲染完成后才会被显示出来，同时在另一个缓存上进行下一帧的渲染。

## 8. 核心知识点总结

### 8.1 渲染管线完整流程图

```
应用阶段 (CPU)
  │  用户输入、碰撞检测、动画、物理模拟、剔除算法
  │  输出: 图素(点/线/三角面)、纹理、参数
  ▼
几何运算阶段 (GPU)
  ├── 顶点着色: 坐标变换、法线/UV输出
  ├── 可选过程: 细分曲面 → 几何着色 → 流输出
  ├── 剪裁: 齐次坐标剪裁
  └── 屏幕映射: → 屏幕坐标
  ▼
光栅化阶段 (GPU)
  ├── 三角面设置: 计算边方程等数据
  └── 三角形遍历: 生成片元(含插值数据)
  ▼
像素运算阶段 (GPU)
  ├── 像素着色: 纹理、颜色计算(可编程)
  └── 合并阶段: Z-Buffer测试、混合(不可编程,可配置)
      └── 输出 → 帧缓存 → 双缓存 → 显示
```

## 9. 延伸思考

1. **管线优化思路：** 找到瓶颈阶段（最慢的阶段）进行针对性优化，如应用阶段的剔除算法减少传入 GPU 的图素数量。
2. **Early-Z 与 Alpha Test 的矛盾：** Early-Z 能大幅提升性能，但一旦像素着色器中涉及片元丢弃或深度修改，Early-Z 就会失效，需要在渲染排序上做权衡。
3. **半透明渲染难题：** Z-Buffer 不支持半透明物体的深度排序，需要从后向前排序绘制（Painter's Algorithm），或不写入深度仅做颜色混合。
4. **可编程管线趋势：** GPU 从固定管线发展至可编程管线，着色器（Shader）赋予了开发者对顶点和像素的完全控制能力，是现代实时渲染技术的基石。
